# Session SA06 — the e2e suite that passed without running

## Objective

Gap 3 of the SA05 handoff: semgrep and dependency-cruiser are only end-to-end
tested where installed, so CI proves less than a local run. Chasing it found
something worse than the gap.

## The finding

The central e2e test — _"every adapter that is installed produces evidence"_ —
loops over the available adapters and `continue`s past the unavailable ones. With
no scanner on `PATH` the loop body never executes: **zero iterations, zero
assertions, green**.

Measured rather than argued. With `PATH` stripped to `/usr/bin:/bin`:

```
✓ tests/e2e/scan.test.ts (7 tests | 6 skipped)
      Tests  1 passed | 6 skipped (7)
```

That is precisely the failure the file's own header warns about — _"a green suite
that never ran is worse than a red one that says why"_ — and it is what CI had
been doing every day, because the `test` job installs no scanner at all.

## The fix

Two counters, both of which must be non-zero:

- **`ran`** — at least one adapter executed. Zero fails with _"no scanner was
  available — this suite passed without running anything"_.
- **`verdicts`** — at least one row is `FAIL` or `PASS`, not only `UNKNOWN`. This
  one matters more than it looks: dependency-cruiser alone would satisfy `ran`
  while reporting a single UNKNOWN row, and a suite that ran and decided nothing
  has still proved nothing.

Watched failing with no scanner, passing with one.

## Making CI satisfy it

The `test` job installs **semgrep**, the one scanner that works there for free —
the fixture already vendors `fixtures/insecure-app/semgrep-rules` and points
`.usa/scanners.yaml` at it, so the run is offline and reproducible. Pinned to
**1.182.0**, the version the adapter was verified against, so CI tests the
measured configuration rather than whatever shipped last week.

Not installed, deliberately: trivy (CVE database), codeql (700 MB), ort (docker),
scorecard (token). Their tests still skip loudly, which is honest — but the suite
as a whole can no longer pass on nothing.

Verified in CI, not just locally: the run log shows `installed package semgrep
1.182.0` and the job green, which is only possible if the new assertions ran and
passed.
