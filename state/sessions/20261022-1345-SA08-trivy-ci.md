# Session SA08 — the second scanner in CI

## Objective

Gap 3 after SA06: one scanner (semgrep) is end-to-end tested in CI, and the rest

## Why trivy and not the others

It is the only remaining scanner that can run in CI for free, and it earns its
place by producing a **different evidence kind** — vulnerability rows carrying CVE
identifiers — rather than more of the same.

Two facts make it safe, and both are properties of the fixture rather than of CI:

- the fixture ships a **committed `package-lock.json`**, force-added past the
  gitignore rule. Without it the CVE evidence silently disappears — a trap already
  recorded in the handoff.
- the e2e asserts only that rows exist and carry `CVE-`-format identifiers. A
  drifting vulnerability database therefore **cannot** turn the test red.

That drift-tolerance is the reason the binary is pinned but the database is not:
pinning the database would make the test stale the moment a CVE is published.

Pinned to **0.75.0**, the version the adapter was verified against.

Not added, each for a stated reason: **codeql** (700 MB bundle), **ort** (docker),
**scorecard** (platform token). They still skip loudly, which is honest.
