# Session SA05 — a failing scanner says why

## Objective

Gap 5 of the SA04 handoff: dependency-cruiser's default target is `src`, and a
project whose sources are elsewhere gets `ok` plus an UNKNOWN row whose reason
reads _"output was not valid JSON"_ when the truth is _"`src/` does not exist"_.
The verdict was already safe; the reason misled.

## Measured first

`depcruise --output-type json --no-config src` in a directory with no `src/`:

|        |                                                                                                       |
| ------ | ----------------------------------------------------------------------------------------------------- |
| stdout | **empty**                                                                                             |
| stderr | a three-line "install me locally" warning, then `ERROR: Can't open 'src' for reading. Does it exist?` |
| exit   | 1                                                                                                     |

So the diagnosis was on stderr the whole time and the adapter never looked at it.

## What changed

`SpawnSuccess` carries stderr. After parse, an **UNKNOWN** row whose process
exited non-zero gets the last non-empty stderr line appended:

```
before  dependency-cruiser output was not valid JSON: Unexpected end of JSON input
after   ... (exit 1: ERROR: Can't open 'src' for reading. Does it exist?)
```

## The boundary, and why it is the real work

Three tests, written before the fix. The annotation test failed on the old code;
the two guards passed both before and after — which is what makes them guards:

- **A FAIL row is never annotated.** A verdict stays exactly what the parser
  produced. Without this, a tool that complained _and_ found something would have
  its verdict quietly rewritten — the same class of bug as the SARIF level one,
  where a reader overwrote what the tool said.
- **A zero-exit UNKNOWN is not annotated.** Nothing failed, so there is no error
  to report; without this, every clean run grows a fake error message.
- The **last** non-empty line, because depcruise prints its warning first and its
  error last. Capped at 200 characters.

## A flake observed, not diagnosed

The first full-suite run reported 4 failures in `tests/e2e/cli.test.ts` and
`tests/e2e/evolution-determinism.test.ts`. A re-run of the entire suite was green,
and both files pass in isolation. That is consistent with the repository's own
documented trap (e2e scanners declare a 15s default that flakes under load) — but
I did not isolate the cause, so the PR body says so rather than claiming flakiness.
